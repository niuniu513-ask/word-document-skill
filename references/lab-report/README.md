# 实验报告类任务的专用资料

本目录只放**实验报告 / 课程设计 / 实践报告**这一类任务的做法。通用 Word 规则不在这里，见上一级 `references/`。

## 为什么要分开

实验报告比"改一份 Word"多出三层东西：真实运行证据（notebook、截图）、按小节对应代码与分析、以及一套按页收口的框线验收。这些做法套到普通文档上会变成负担；反过来，拿通用 Word 规则去做实验报告，会漏掉证据链和逐页配对。

所以按适用范围分三档，写文档时对号入座：

| 档次 | 含义 | 能不能直接套到新任务 |
|---|---|---|
| **通用规则** | 任何 .docx 都成立：样式继承、字体轨道、锚点插入、渲染验收 | 能，见 `references/` 根目录 |
| **本类方法** | 实验报告都适用：证据采集路线、验证码链、逐页配对检查 | 能，按本次模板重新取值 |
| **个案记录** | 某次实验的具体数字与参数：页宽、字号、图片数、框线坐标 | **不能**，只作参照 |

写文档时把这三档混在一起，最典型的后果是把某次实验的 880px 页宽、15.2cm 版心、25 张图当成通用常量，下一次换模板就全部对不上。

## 文件

| 文件 | 档次 | 内容 |
|---|---|---|
| [lab-report-config.md](lab-report-config.md) | 本类方法 | `lab_report.py` 的配置字段：显式映射、容器、原型段落、分组、思考题；不含任何具体数值 |
| [capture-offscreen.md](capture-offscreen.md) | 本类方法 + 个案记录 | 离屏渲染采集截图的流程与参数；参数表标注为实测个案 |
| 上级 `references/screenshot-evidence.md` | 通用规则 | 什么算真实截图、缩放换算、裁切与像素保真 |
| 上级 `references/template-frames.md` | 通用规则 | 大框/单格容器的识别与分页 |

## 执行顺序

端到端逐关流程在 `workflows/lab-report-runbook.md`，本目录只提供其中两关的细节。按关卡的依赖关系读：

```text
1 模板分析（通用）→ 2 notebook 执行 → 3 截图采集（本目录）→ 4 配图核对
→ 5 按配置填充（本目录 config）→ 6 逐页验收（通用 visual-qa）→ 7 交付
```

## 个案参数怎么记

需要记录某次实验的具体取值时，写在该文档的"实测个案"小节里，并注明：日期、模板、版心宽度、页数、图片数、以及**为什么取这个值**。不要把个案值写进正文的祈使句（"应设为 880px"），那会被下一次当成规范照抄。

判断依据很简单：**换一份模板、换一个学科，这句话还成立吗？** 不成立就是个案，必须标注。

## 复用前的三件事

1. 重新跑一遍模板分析，拿到本次的真实版心宽度、原型段落索引、框线坐标——这些每次都不一样。
2. 截图参数按本次的字号需求重算，不要继承上次的页宽（换算公式在 `capture-offscreen.md`）。
3. 验收标准按本次的模板结构重写，尤其是"一页一个框"这类要求，取决于原模板是不是连续大框。
