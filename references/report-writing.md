# 报告类文档写作(Report Writing)

实验报告、实习报告、课程设计、实践报告等是本 Skill 最高频的场景。**这些结构只是默认值;用户模板有明确结构时,模板永远优先**(铁律优先级链第 2 条 > 本文件全部内容)。

## 1. 实验报告(默认结构)

实验目的 / 实验原理 / 实验仪器 / 实验步骤 / 数据记录与处理 / 实验结果 / 结果分析 / 误差分析 / 问题讨论 / 实验总结。

写作要点:

- 原理:公式 + 文字推导,交代每个符号含义;不要教科书式抄写,压缩到与本次实验直接相关的部分。
- 步骤:按操作时序,句式"用××测量××,重复×次";不写感受。
- 数据:全部进表格;有效位数与仪器分度值一致(米尺 1mm → 长度记到 0.1mm 或 1mm,不出现 55.000);重复测量列多列原始值,再给平均值。
- 结果:给出均值 ± 不确定度(大学物理类:A 类+B 类合成),与参考值比较给相对误差/偏差。
- 误差分析:具体到本次测量(仪器分度值、读数时机、环境),不写"人为误差不可避免"这类空话。
- 数据缺失:表格留 `【待补充】`,并在交付说明里列出;**严禁编数**。用户明确说"帮我编一组合理数据"时,数值标注 `【模拟数据】` 且尽量物理自洽。

## 2. 实习报告(默认结构)

实习单位概况 / 实习岗位与时间 / 实习目的 / 实习内容与过程 / 主要工作与成果 / 专业知识的应用 / 遇到的问题及解决 / 实习收获与体会 / 总结。

要点:单位信息、时间、岗位必须来自用户资料;过程写具体任务(做了什么系统/报表/流程),收获对应到能力点;没有的经历宁缺毋滥,提示用户补充。

## 3. 课程设计/实践报告(默认结构)

设计任务与要求 / 总体方案 / 详细设计(分模块)/ 调试过程 / 测试结果 / 总结与展望 / 参考文献。代码关键片段可放附录;图表编号连续(图 1、表 1 各自独立计数)。

## 4. 图表规范(适用于全部报告)

- 图:正文引用"如图 1 所示"必须在图前出现;题注在图**下方**,居中;插入时保持原始纵横比(只给 width_cm)。
- 表:题注在表**上方**(国标习惯;模板另有惯例从模板),居中;表头加粗;三线表/网格线以模板为准。
- 单位用国标符号(m、s、kg、℃);数字范围用"~";百分号前保留合适位数。

## 5. 文风

- 客观陈述,第一人称克制使用("本实验""本次实习"优于"我")。
- 不用"首先/其次/最后"的机械路标堆砌;步骤用编号列表,分析用因果句。
- 篇幅以模板/用户要求为准;没说时:正文各节均衡,原理与数据分析最重,结论 150-300 字。

## 6. 含截图的报告(代码 + 运行结果)

编程类实验(python/numpy/pandas/matplotlib、C、Java)的模板常自带三段式:

```
第 N 题 <题目原文>
代码截图：
<图>
实验结果截图：
<图>
分析：<2-4 句>
```

规则:

- **一题一段**:图紧跟在标签段落之后,不要把上一题的图留到下一题标题下。
- **有代码无输出**(纯 `import`、纯赋值、`plt.show()` 被吞):删掉"实验结果截图:"标签,只留代码图。留个空图等于告诉读者程序崩了。
- **分析写什么**:这段代码做了什么 + 输出说明了什么 + 与题目要求的对应关系。不要复述代码逐行翻译。
- 分析中的实测数字需追溯到对应输出图或执行记录;理论值、倍数或均值的推导须说明依据。索引、类别计数不要凭记忆填写。
- 图注按模板;模板没要求就不加,避免"图 1"编号与模板已有的编号打架。
- 一页放不下时,允许代码图与输出图跨页,但**不要**把标签留在页尾、图在下一页(用 keep-next 或手工分页)。

采集、裁切、入 Word 的比例换算见 `references/screenshot-evidence.md`;端到端流程见 `workflows/lab-report-screenshots.md`。

## 7. 与脚本的配合

- 报告正文的每一节写成 content.json 的锚点块(`after` = 模板对应标题原文)。
- 数据表:`table` 块 + caption;模板已有空数据表用 `table_fill`。
- 公式:纯文本形式(T=2π√(L/g));复杂公式建议留 `【待补充:公式(6)】` 让用户用公式编辑器插入,或使用 OMML XML(仅在用户要求且你确认渲染正常时)。
