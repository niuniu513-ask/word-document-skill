# 视觉检查(Visual QA)

Phase 4 的操作规程。**渲染成功 ≠ 排版正确**——只有逐页看过渲染图才算检查过。

## 1. 渲染

```bash
python <skill>/scripts/render_docx.py 文档.docx -o 渲染目录 --dpi 110 --update-fields
```

- 后端自动选择:Word COM(pywin32,与最终用户看到的 Word 效果一致,首选)→ LibreOffice headless 兜底。
- `--update-fields`:导出前更新 TOC/页码等所有域并回存 docx。凡内容增删过,必加此参数;它会让渲染慢几秒,值得。
- `--pages 1-5` 只渲染部分页(快速复查某几页时用);`--pdf-only` 只要 PDF。
- 每页输出 `page-001.png` 起连续命名,JSON 摘要含页数与后端。
- Word COM 失败常见原因:文件被占用(用户开着 Word)→ 复制一份再渲染;路径含特殊字符 → 用绝对路径;首次调用慢(Word 冷启动)属正常。

## 2. 逐页检查清单

用 Read 工具逐张看 PNG,每页过一遍:

| 检查项 | 典型表现 |
|---|---|
| 空白页/大面积空白 | 中间夹一张几乎全空的页;最后一页只有一行 |
| 标题孤立 | 标题在页尾,内容在下一页 |
| 图片变形 | 图片被拉扁/拉长,圆变椭圆 |
| 图片溢出 | 图片超出版心,或与文字重叠 |
| 表格溢出 | 表格超出右边界;单元格文字竖排挤压 |
| 表格断裂 | 表头在上一页,数据在下一页且无重复表头 |
| 页眉/页脚丢失 | 某节页眉空白(对比原文档渲染) |
| 页码异常 | 封面出现页码;目录页码与实际不符;页码跳号 |
| 边距异常 | 正文顶到页边;与原文档渲染对比明显不同 |
| 字体/行距异常 | 一段字体突兀不同;行距忽大忽小 |
| 编号异常 | 编号断档、重复、层级错乱 |
| 中文异常 | 乱码、问号、方框(字体缺失) |

页数多时优先看:首页(封面)、目录页、每个新章节起始页、表格/图片所在页、最后一页。

### 截图证据专项(含截图的报告必查)

| 检查项 | 典型表现 |
|---|---|
| 标签与图错位 | "代码截图:"下面紧跟着上一题的图;图挂在下一题标题之后 |
| 字号失配 | 图里的代码字比正文标题还大,或小到要放大才能读 |
| 宽黑条 | 图很宽,内容只占左侧一小块,右侧整片纯色 |
| 纯色块 | 整张图几乎全黑/全白(没有输出的单元格被插了空图) |
| 拉伸变形 | 表格文字变扁、圆变椭圆(同时设了宽和高) |
| 图注缺失/重复 | 有的图有"图 N",有的没有;编号跳号 |
| 结论对不上 | 正文写"出现 5 次",图里是 4 次 |

数量层面的核对不要靠眼睛,跑 `scripts/verify_evidence.py`:标签数、图片数、空图、宽黑条、变形一次报全。目检负责"位置和观感",脚本负责"数量和比例",两者都要过。

## 3. 修复循环

发现问题 → references/repair-rules.md 对症下药 → `repair_docx.py --apply` 或手改 → 重新渲染 → 重新检查。**最多 3 轮**;3 轮后仍有问题:能修的修完,修不了的如实列入交付说明(哪个问题、哪一页、怀疑原因)。禁止:渲染完不看图就交付;看图发现问题却跳过修复;无限循环重试同一修复。

## 4. 修复前后对比

重大修改(修复 >3 处、rebuild、格式迁移)建议渲染两套:修改前/修改后,页数应一致或符合预期;页数突变(±1 以上)几乎总有排版事故,先找原因再交付。

## 5. 已知后端差异

- LibreOffice 渲染中文字体替换更激进(缺字体会换思源/文泉驿),行距略宽——视觉检查结论以 Word COM 为准,LibreOffice 结果仅供兜底。
- 渲染图的轻微锯齿/压缩痕迹不是文档问题,别修。
