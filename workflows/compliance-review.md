# 合规体检工作流(Compliance Review)

用于"这份文档能不能交/能不能报审"的判断。它是 analyze → 规则包 → 结论 的封装，
把"格式是否规范"从主观印象变成可复现的分数与清单。

## 何时用

- 用户问："我这份方案能报审吗/能交吗/格式有没有问题"。
- 用户要在提交前自查，且没有时间逐条核对模板要求。
- 你需要向第三方(老师、监理、评审)给出一个客观结论，而不是"我觉得还行"。

## 一条命令

```bash
python scripts/review.py 方案.docx                                   # 默认 railway-plan 规则包
python scripts/review.py 实验报告.docx --profile lab-report --html 体检.html
python scripts/review.py 改后.docx --baseline 原件.docx               # 附加:格式漂移检查
```

产物:

| 参数 | 产物 |
|---|---|
| 默认 | 终端输出 Markdown 报告 |
| `-o r.md` | 报告写入文件 |
| `--html r.html` | 自包含 HTML(可直接截图进答辩材料) |
| `--json r.json` | 机器可读结果(分数、等级、findings、facts) |

退出码:`0` 无阻断项;`1` 有阻断项(可用于 CI 卡口);`2` 文件或规则包错误。

## 怎么读报告

报告分三段:

1. **检查项表格** —— 必备章节、标题数、正文段数、表格数、占位符、正文字号、页面尺寸,每项一个 ✅/❌。
2. **问题清单** —— 每条问题带 `位置` / `详情` / `怎么改`,按阻断 → 严重 → 提示排序。
3. **文档事实** —— 所有抽取到的数值(JSON),便于复查结论是怎么来的。

定级口径:阻断 = 交上去一定被打回(缺必需章节、留占位符、格式漂移);严重 = 大概率被要求返工(缺页码域、层级跳级、字号不符);提示 = 影响观感但不影响受理。

## 规则包(换单位只改 JSON)

内置三套,位于 `rules/`:

| id | 面向 | 关键约束 |
|---|---|---|
| `railway-plan` | 铁路施工方案报审自查 | 10 个必备章节、A4、需 PAGE 域、正文 10.5–16 pt |
| `lab-report` | 课程实验报告 | 7 个必备章节(目的/原理/器材/步骤/结果/分析/结论) |
| `generic` | 通用文档 | 只查结构健康度:层级、占位符、空段落、表格 |

新增一套 = 复制一份 JSON 改字段,不改代码。字段说明见 `references/compliance-rules.md`。

## 与修复闭环的衔接

```
review.py(发现问题)
   ↓ 能自动改的:编号、空段落、页码域、字体系
repair_docx.py --fix ... --apply -o 修后.docx
   ↓ 内容要人补的:逐条按"怎么改"补
review.py 修后.docx            → 复检,分数应上升
validate_docx.py --original 原件.docx --final 修后.docx   → 证明只改该改的
```

**顺序不能反**:先 validate 再修,等于没有基线;先修不 review,等于不知道还差什么。

## 局限(必须对用户讲清)

- 只判断"格式与要素",不判断技术方案本身是否可行、参数是否正确。
- 必备章节靠标题文字匹配(别名表),标题写得面目全非会漏判——这时报告会显示"缺少",应当人工确认而不是直接补标题。
- 占位符计数是"含占位符的段落/单元格数",不是出现次数。
- 字体取"主题字体"时会被还原成 docDefaults 里的实际字体;若文档主题缺失,可能显示为备份值。
